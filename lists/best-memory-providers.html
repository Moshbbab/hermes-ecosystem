For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

This universal memory layer provides multi-level storage for user, session, and agent states using temporal reasoning and multi-signal retrieval. It is available as an Apache-2.0 self-hosted server, an OSS SDK, or a managed cloud service.

volcengine / OpenViking

OpenViking organizes context as a virtual filesystem using viking:// URIs and a tiered L0/L1/L2 loading system to reduce token consumption. This AGPL-3.0 context database provides observable retrieval trajectories for debugging and achieved significant task-completion gains in LoCoMo10 testing.

topoteretes / cognee

Cognee is a self-hosted knowledge graph engine designed to give agents persistent long-term memory across multiple sessions. It supports unified ingestion of multimodal data and offers Python, Rust, and TypeScript clients alongside a local UI.

garrytan / gbrain

This opinionated agent brain builds knowledge graphs using typed edges without requiring LLM calls to generate the structure. It features scoped institutional memory with per-user data isolation and produces cited prose answers with explicit gap analysis.

supermemoryai / supermemory

This engine features a custom vector graph engine that supports sub-300ms recall at scales exceeding 100B tokens per month. It automates fact extraction and user profiling while offering connectors for platforms like Google Drive, Notion, and GitHub.

vectorize-io / hindsight

Hindsight implements long-term retain, recall, and reflect workflows to help agent memory learn over time. It supports over 25 LLM providers and is deployable via Docker, Kubernetes, or managed cloud environments.

plastic-labs / honcho

Honcho is a memory library for building stateful agents, serving as the upstream foundation for the Hermes self-hosted wrapper. Its core logic is implemented as a FastAPI server that provides SDKs for managing sessions and peer interactions.

campfirein / byterover-cli

This Elastic License 2.0 provider treats memory as a git repository, utilizing version control actions like commit, branch, and merge for context tree management. It employs a 5-tier retrieval system where four tiers are non-LLM based to ensure sub-100ms performance.

mnemosyne-oss / mnemosyne

Mnemosyne is a zero-dependency, sub-millisecond memory system that utilizes a single SQLite database for local storage. It integrates via MCP, Python SDK, or OpenWebUI and requires only Python 3.10 and one pure-Python dependency.

ClaudioDrews / memory-os

This seven-layer memory system utilizes Qdrant, Redis, and SQLite to manage vector search, structured facts, and an auto-curated wiki. It employs a Ground Truth hierarchy to ensure agents prioritize specifically injected context during execution.

greyhaven-ai / autocontext

Autocontext is a recursive self-improving harness that produces filesystem-first artifacts such as traces and context bundles. It features outcome-gated promotion and ablation-backed attribution to refine context changes based on task success.

stephenschoettler / hermes-lcm

This plugin provides lossless context management through a hierarchical DAG-based engine that ensures no messages are lost. It includes specialized recall tools like lcm_grep and lcm_recall for recovering specific details from its SQLite store.

vshulcz / deja-vu

This tool indexes existing local session history from 22 supported coding agents to enable millisecond lookups over gigabytes of historical data. It allows agents to search months of past sessions while ensuring safety by redacting keys and tokens during the indexing process.

elkimek / honcho-self-hosted

Honcho provides a self-hosted backend that enables private cross-session memory for Hermes Agent using Docker, PostgreSQL, and Redis. It supports local inference servers or any OpenAI-compatible LLM provider to maintain persistent state across sessions.

Signet-AI / signetai

This local-first identity and memory layer maintains a living semantic ontology with audit trails linked to raw data sources. It achieves 97.6% average LongMemEval answer accuracy and provides portable state across Hermes Agent, Claude Code, and Gemini CLI.

plur-ai / plur

Plur functions as a shared memory layer that stores data as human-readable YAML files on a local disk. It utilizes a hybrid search mechanism combining BM25 and local embeddings to provide retrieval capabilities for MCP-compatible tools.

yoloshii / ClawMem

ClawMem is an on-device context engine that operates locally without cloud dependencies or API keys. It integrates via MCP and plugins, employing a hybrid retrieval system of BM25 and vector search to manage agent memory.

EfficientContext / ContextPilot

This project optimizes long-context inference by reordering and deduplicating blocks to facilitate prefix reuse. It offers native plugin support for Hermes Agent, reducing prefill latency by 1.5–3× and saving up to 36% of tokens.

Sibyl-Labs / Sibyl-Memory

Sibyl-Memory is a file-based long-term memory system that uses SQLite with FTS5 search instead of vector databases or embeddings. The five-package plugin family includes a dedicated Hermes adapter and a LangGraph BaseStore for durable storage.

yantrikos / yantrikdb-hermes-plugin

This self-maintaining plugin provides explainable recall by attaching a 'why_retrieved' tag to every result and uses a self-directing loop to resolve knowledge gaps. It supports owner-scoping for multi-user environments like Discord or Telegram and includes contradiction tracking.

ccf / agentcairn

AgentCairn uses an Obsidian vault as the source of truth, storing cross-project memory as inspectable Markdown files. It runs locally without a daemon or telemetry, utilizing DuckDB as a replaceable retrieval cache.

yepyhun / Brainstack

Brainstack acts as a memory kernel stack that integrates Hindsight, Graphiti, and MemPalace into a single memory owner. It manages state and retrieval using SQLite, Kuzu, and Chroma to deliver specific evidence packets to the agent for each query.

amanning3390 / flowstate-qmd

This anticipatory memory system prefetches context by monitoring agent session logs and storing data locally via SQLite-vec. It is an MCP-native server designed for major coding agent clients, utilizing GGUF models for local processing.

Perseus-Computing-LLC / perseus

Perseus resolves live workspace state into verified facts before the context window opens, utilizing a local-first architecture with SQLite and FTS5. It supports the Model Context Protocol (MCP) and aims to reduce prompt tokens by up to 94%.

generalbusiness-ai / keep

This provider enables reflective memory through semantic search using BM25 full-text and ranked graph traversal. It automates indexing for codebases, URLs, and multimedia with OCR support, utilizing edge tags to create navigable, bidirectional relationships between notes.

alias8818 / hermes-tool-slimmer

This tool reduces prompt token overhead for Hermes Agent v0.14.0 by using local BM25 ranking to select relevant tool schemas. It includes a dashboard for tracking estimated token savings and supports native tool search functionality.

Ladybug-Memory / hermes-memory-plugin

A local-only plugin that stores data in a single .lbdb embedded graph database file with optional GLiNER2 entity extraction. It features importance-weighted recall to surface high-priority memories during context prefetch alongside BM25 keyword search.

conorbronsdon / claude-context-os

This Git-backed layer uses Markdown files as a durable source of truth for context across Claude Code, Codex, and OpenClaw. It provides a dedicated migration workflow for importing existing chats and project instructions into the agent's environment.

MukundaKatta / hermes-agentmemory

This episodic memory plugin focuses on data integrity by supporting real, immediate event deletion and providing a trace.jsonl audit log of all operations. It utilizes an on-demand summarizer and serves as a community fix for specific Hermes Agent recall issues.

piprail / piprail

This SDK and MCP server allows agents to handle payments using USDC and stablecoins across 29 chains, including EVM and Solana. It integrates with Hermes to enable agents to pay for services or charge for their own API usage with 0% transaction fees.

stepanov1975 / hermes-local-knowledge

This plugin indexes local skills, scripts, runbooks, and MCP configurations to improve agent routing. It offers tools for artifact search and graph neighbor traversal, utilizing implicit and explicit feedback to refine its local routing hints.

yonro / hermes-xmemo-plugin

XMemo provides durable cross-session memory through pre-turn context injection and session-end snapshots. The system ensures reliability via a local SQLite layer and a write outbox for managing state updates and searches.

futurebrowser / hermes-exabase-plugin

Integrating Exabase M-1, this plugin provides self-organizing long-term memory for Hermes agents. It supports configurable query expansion and result reranking to optimize the retrieval of manually stored or searched memories.

visorcraft / MongrelDB-Hermes

This AI-native memory provider features AES-256-GCM encryption at rest and supports HNSW ANN, sparse, and FM-index retrieval. It can be deployed via native Rust FFI or an HTTP daemon and includes MinHash deduplication and metadata filters.

sourcevault-ai / sourcevault-code-tools

This plugin provides private local code memory for repositories through deterministic slash commands and LLM-callable tools. It requires a local SourceVault server to handle indexing, vector storage, and grounded Q&A operations.

penfieldlabs / hermes-penfield

Penfield offers 17 tools for memory management and knowledge graph traversal using a hybrid search of BM25, vector, and graph methods. It also features automatic context checkpointing to preserve information during message compression.

conorbronsdon / agent-memory-kit

This project provides a file-based curation loop that identifies data rot and contradictions within agent memory using a git-backed directory of markdown files. It features five slash commands for capturing and recalling information while generating evidence-cited diffs for manual review and JSON output.
