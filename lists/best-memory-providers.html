For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

An official Hermes Agent memory provider that offers a universal memory layer for user, session, and agent states. It supports temporal reasoning and multi-signal retrieval through an Apache-2.0 self-hosted server, SDK, or managed cloud.

vectorize-io / hindsight

This memory system enables long-term retain, recall, and reflect workflows across more than 25 LLM providers. It provides client libraries for Python, Node.js, and Go, with deployment options ranging from CLI and Docker to managed cloud.

volcengine / OpenViking

An official Hermes Agent memory provider that organizes context as a virtual filesystem using viking:// URIs. It utilizes a three-tier loading architecture (Abstract, Overview, Details) to achieve significant token reduction and improved task completion rates.

topoteretes / cognee

A self-hosted knowledge graph engine that provides AI agents with persistent long-term memory across sessions. It builds searchable graphs from text, code, and conversations and can run locally on a CPU without external LLM API keys.

supermemoryai / supermemory

An official Hermes Agent memory provider featuring a custom vector graph engine that sustains sub-300ms recall at high volumes. It supports multi-modal extraction and maintains auto-updated user profiles with context fencing and byte-level deduplication.

garrytan / gbrain

This opinionated agent brain stores facts with provenance, allowing for corrections and withdrawals of stored information. It includes a synthesis layer for cited answers and exposes memory to agents via MCP over Tailscale or local connections.

plastic-labs / honcho

The upstream library for the honcho-self-hosted Hermes wrapper, designed for building stateful agents via a FastAPI server. It tracks peer-centric representations and session context through background reasoning using Python and TypeScript SDKs.

campfirein / byterover-cli

An official Hermes Agent memory provider that manages a plain markdown context tree using git-like version control features such as branching and merging. It offers a 5-tier retrieval system with sub-100ms performance and an interactive TUI.

mnemosyne-oss / mnemosyne

A zero-dependency memory system for Hermes Agents that requires only Python 3.10+ and a single SQLite database. It delivers sub-millisecond performance and features episodic compression to manage storage growth at scale.

moorcheh-ai / memanto

This system extracts durable knowledge from ephemeral conversation streams and reconciles conflicting information by superseding old beliefs. It allows for the export of memory estates as plain Markdown via the Open Knowledge Format.

ClaudioDrews / memory-os

A seven-layer memory system for Hermes Agent that utilizes a Ground Truth hierarchy to prioritize injected context. It runs on local infrastructure including Qdrant, Redis, and SQLite to manage structured facts and an auto-curated wiki.

greyhaven-ai / autocontext

A recursive self-improving context harness that generates playbooks and training artifacts from task runs to assist agents with complex tasks. It supports various LLM endpoints and provides entry points via CLI, MCP server, and Pi extensions.

stephenschoettler / hermes-lcm

This plugin utilizes a hierarchical DAG and SQLite store to ensure message persistence without data loss. It provides specific recall tools like lcm_grep and lcm_recall to help Hermes Agent recover specific details from its context history.

vshulcz / deja-vu

This tool indexes session history from 35 different coding agents to provide shared cross-tool memory without using models or external servers. It tracks file edits and command statuses locally, allowing users to search through months of past sessions.

elkimek / honcho-self-hosted

This self-hosted backend enables private cross-session memory for Hermes Agent using Docker, PostgreSQL, and Redis. It supports various OpenAI-compatible LLM providers and local inference servers for persistent data storage.

Signet-AI / signetai

This local-first identity and memory layer offers portable state across multiple clients and supports real-time ingestion from Obsidian, Discord, and GitHub. It demonstrates high performance on LongMemEval benchmarks for accurate information retrieval.

plur-ai / plur

This shared memory layer stores information as human-readable YAML engrams on local disk for use across multiple coding agents. It employs local-first retrieval methods, including BGE-small and optional rerankers, to manage agent context.

yoloshii / ClawMem

Operating entirely locally without cloud dependencies, this engine captures agent decisions and preferences from session transcripts. It retrieves information by fusing BM25, vector search, and multi-graph traversal techniques.

Sibyl-Labs / Sibyl-Memory

This five-package plugin family provides durable, file-based long-term memory using a SQLite-backed hierarchical schema and FTS5 search. It is designed to function without vector databases or embedding models across Linux, macOS, and Windows.

EfficientContext / ContextPilot

This tool optimizes long context inference by reordering text and multimodal data to facilitate prefix-cache sharing. It integrates with various inference engines to provide cache-aware scheduling and context deduplication.

yantrikos / yantrikdb-hermes-plugin

This embedded in-process backend provides explainable retrieval by tagging every recalled item with a reason for its selection. It features built-in primitives for tracking contradictions and resolving conflicts within the agent's memory.

ccf / agentcairn

This daemonless system uses an Obsidian vault as the source of truth, storing durable memory as inspectable Markdown files. It utilizes a local DuckDB cache for hybrid search and integrates with agents via MCP servers.

JanYork / llm-wiki-cli

This CLI tool allows agents to autonomously maintain and evolve persistent knowledge stored in local SQLite and Wiki files. It also supports team synchronization through a self-hosted server with integrated permission controls.

amanning3390 / flowstate-qmd

This MCP-native server uses an anticipatory cache to prefetch context by monitoring agent session logs. It relies on local-first storage via SQLite-vec and processes GGUF models to manage memory for coding agents.

yepyhun / Brainstack

This memory kernel stack integrates Hindsight, Graphiti, and MemPalace into a single owner to manage state and retrieval via SQLite, Kuzu, and Chroma. It provides the agent with a purpose-built evidence packet for each query to streamline information processing.

generalbusiness-ai / keep

Keep provides reflective memory for agents using semantic search, BM25 full-text indexing, and ranked graph traversal. It features automated indexing for codebases and multimedia with OCR support, utilizing edge tags to create navigable, bidirectional relationships between notes.

aliasocracy / hermes-tool-slimmer

This project reduces prompt token overhead for Hermes Agent v0.14.0 by using local BM25 tool ranking to select relevant keyword-based schemas. It includes a dedicated dashboard for tracking estimated token savings and supports native tool search functionality.

conorbronsdon / agent-context-os

Agent Context OS serves as a Git-backed context and workflow layer for coding agents like Claude Code and Codex. It uses a migration workflow to convert chats and documents into reviewable files, requiring manual approval for context proposals and integration.

Ladybug-Memory / hermes-memory-plugin

This local-only plugin uses a single .lbdb embedded graph database to surface high-priority memories through 1-10 importance-weighted recall. It supports BM25 keyword search, named graph relationships, and optional GLiNER2 entity extraction for structured memory management.

MukundaKatta / hermes-agentmemory

This pull-model episodic memory plugin features an on-demand summarizer and a trace.jsonl audit log for tracking every memory operation. It distinguishes itself by supporting real, immediate event deletion to prevent persistent summaries from affecting future recall.

stepanov1975 / hermes-local-knowledge

This plugin indexes local skills, scripts, runbooks, and MCP server configurations to provide concise system-prompt hints via session hooks. It offers five native tools for artifact search, retrieval, and feedback to improve agent routing capabilities.

piprail / piprail

Piprail provides a TypeScript SDK and MCP server that enables agents to handle x402 payments using USDC and stablecoins across multiple chain families. The system operates without a backend, database, or API keys, allowing for budget-bound agent wallets.

yonro / hermes-xmemo-plugin

XMemo enables cross-session continuity by allowing agents to read memories from other connected agents through native lifecycle hooks. It utilizes a local SQLite layer for caching and write outbox reliability during pre-turn recall and session-end snapshots.

futurebrowser / hermes-exabase-plugin

This plugin integrates Exabase M-1 for self-organizing long-term memory, providing tools for both manual storage and automated searching. It supports configurable query expansion and result reranking to refine the retrieval process for the agent.

sourcevault-ai / sourcevault-code-tools

SourceVault provides private local code memory for repositories, supporting semantic search and grounded Q&A through a local server. It adds deterministic slash commands and LLM-callable tools for indexing, syncing, and reading files.

visorcraft / MongrelDB-Hermes

This memory provider offers AES-256-GCM encryption at rest and supports retrieval via HNSW ANN, sparse, and FM-index methods. It can be executed through native Rust FFI or as an HTTP daemon, featuring MinHash deduplication and metadata filters.

penfieldlabs / hermes-penfield

This provider offers 17 tools for memory management and knowledge graph traversal, utilizing a hybrid search approach that combines BM25, vector, and graph methods. It further supports agent efficiency through automatic context checkpointing during message compression.

conorbronsdon / agent-memory-kit

This file-based curation loop identifies 'rot' and contradictions within markdown files to propose evidence-cited JSON diffs for review. It functions without a database, instead leveraging a local git repository to track, manage, and revert changes to the agent's memory.
