For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

This official Hermes Agent memory provider offers a universal layer for managing multi-level User, Session, and Agent states. It supports temporal reasoning and multi-signal retrieval through an OSS SDK, self-hosted server, or managed cloud environment.

volcengine / OpenViking

OpenViking is an official context database that organizes information as a virtual filesystem using viking:// URIs. It utilizes a three-tier loading system to achieve a 91% token reduction and provides observable retrieval trajectories for debugging context paths.

topoteretes / cognee

This platform enables persistent long-term memory through a self-hosted knowledge graph engine that supports unified ingestion and multimodal data. It provides Python, Rust, and TypeScript clients alongside a local UI for managing cross-session agent memory.

garrytan / gbrain

This opinionated agent brain generates cited prose answers and performs explicit gap analysis to identify missing information. It builds knowledge graphs using typed edges without LLM calls and ensures data isolation for scoped institutional memory.

supermemoryai / supermemory

An official memory provider featuring sub-300ms recall and byte-level deduplication for efficient prompt caching. It automates fact extraction and user profiling while integrating data from Google Drive, Gmail, Notion, and GitHub.

vectorize-io / hindsight

Hindsight provides long-term retain, recall, and reflect workflows that allow agent memory to learn over time. It supports over 25 LLM providers and offers flexible deployment options including Docker, Kubernetes, and managed cloud.

plastic-labs / honcho

This library serves as the core FastAPI-based logic for building stateful agents and acts as the upstream foundation for the honcho-self-hosted Hermes wrapper. It includes Python and TypeScript SDKs specifically designed for session and peer management.

campfirein / byterover-cli

This official provider manages context trees using git-like version control, including commit, branch, and merge operations. It features a 5-tier retrieval system where four tiers are non-LLM based, enabling sub-100ms response times via a TUI or REPL interface.

mnemosyne-oss / mnemosyne

A zero-dependency memory system for Hermes Agents that achieves sub-millisecond performance using a single SQLite database for local storage. It integrates via MCP, Python SDK, or OpenWebUI and requires only Python 3.10 and one pure-Python dependency.

ClaudioDrews / memory-os

This seven-layer system utilizes Qdrant, Redis, and SQLite to manage persistent memory, structured facts, and an auto-curated wiki. It employs a Ground Truth hierarchy to ensure agents prioritize specific injected context during task execution.

greyhaven-ai / autocontext

This recursive harness produces filesystem-first artifacts like playbooks and context bundles to help agents succeed on complex tasks. It features outcome-gated promotion and ablation-backed attribution to validate the effectiveness of context changes.

stephenschoettler / hermes-lcm

A Lossless Context Management plugin that uses a hierarchical DAG and SQLite store to ensure no messages are lost. It provides specialized recall tools, such as lcm_grep and lcm_recall, to help Hermes Agents recover specific details from history.

vshulcz / deja-vu

This project indexes existing local session history from 22 supported coding agents to enable millisecond lookups over months of past data. It prioritizes safety by redacting keys and tokens during the indexing process.

elkimek / honcho-self-hosted

This self-hosted backend provides private cross-session memory for Hermes Agent using Docker, PostgreSQL, and Redis. It supports any OpenAI-compatible LLM provider or local inference servers for persistent storage.

Signet-AI / signetai

Signetai maintains a living semantic ontology through a background dreaming process to provide a portable identity and memory layer. It supports real-time ingestion from GitHub, Discord, and Obsidian for use across multiple agent harnesses.

plur-ai / plur

This shared memory layer stores data as human-readable YAML files on local disk using an open engram format. It utilizes a hybrid search combining BM25 and local embeddings to retrieve information for MCP-integrated tools.

yoloshii / ClawMem

ClawMem is an on-device context engine that operates locally without API keys or cloud dependencies. It employs hybrid retrieval, including vector search and BM25, to provide memory via MCP and agent hooks.

EfficientContext / ContextPilot

This tool optimizes context through block reordering and deduplication to enable prefix reuse and reduce prefill latency by 1.5–3×. It offers native plugin support for the Hermes Agent ecosystem to save up to 36% in token usage.

Sibyl-Labs / Sibyl-Memory

Sibyl-Memory is a file-based long-term memory system that uses SQLite with FTS5 search instead of vector databases or embeddings. It is delivered as a five-package plugin family, including a dedicated Hermes adapter.

yantrikos / yantrikdb-hermes-plugin

This self-maintaining plugin provides explainable recall by attaching a why_retrieved tag to every result. It features a self-directing loop to resolve knowledge gaps and supports owner-scoping for multi-user environments.

ccf / agentcairn

Agentcairn uses an Obsidian vault as the source of truth, storing memory as inspectable Markdown files. It runs locally without a daemon or telemetry, utilizing DuckDB as a replaceable retrieval cache.

yepyhun / Brainstack

This memory kernel stack integrates Hindsight, Graphiti, and MemPalace to manage state via SQLite, Kuzu, and Chroma. It is designed to provide agents with a purpose-built evidence packet for every query.

amanning3390 / flowstate-qmd

Flowstate-qmd is an anticipatory memory system that prefetches context by monitoring agent session logs. It uses SQLite-vec and GGUF models for local-first storage and provides an MCP-native server for automated configuration.

Perseus-Computing-LLC / perseus

Perseus resolves live workspace state into verified facts before the context window opens to reduce prompt tokens by up to 94%. It features a local-first architecture using SQLite and FTS5 with native Model Context Protocol support.

generalbusiness-ai / keep

This provider enables reflective memory through semantic search using BM25 full-text and ranked graph traversal. It automates indexing for codebases and multimedia via OCR, utilizing edge tags to create navigable, bidirectional relationships between stored notes.

alias8818 / hermes-tool-slimmer

This tool reduces prompt token overhead for Hermes Agent v0.14.0 by utilizing local BM25 tool ranking to select relevant schemas. It includes a dashboard for tracking estimated token savings and supports native tool search functionality.

Ladybug-Memory / hermes-memory-plugin

A local-only plugin that stores data in a single .lbdb embedded graph database file and uses 1-10 importance ranking to surface high-priority memories. It features BM25-first retrieval, named graph relationships, and optional GLiNER2 entity extraction.

conorbronsdon / claude-context-os

This Git-backed layer manages context and workflows for coding agents like Claude Code and Codex by storing identity and decisions in plain Markdown files. It facilitates a source-neutral migration workflow for documents and chat histories across supported agents.

MukundaKatta / hermes-agentmemory

This episodic memory plugin features a pull-model with an on-demand summarizer and supports real, immediate event deletion to prevent persistent summaries from affecting future recall. It provides a trace.jsonl audit log for monitoring all memory and prefetch operations.

piprail / piprail

This SDK and MCP server allows Hermes agents to handle payments using USDC and stablecoins across 29 chains, including EVM and Solana. It enables agents to charge for APIs or pay for services with 0% transaction fees settled directly to wallets.

stepanov1975 / hermes-local-knowledge

This plugin indexes local skills, scripts, and MCP server configurations to improve agent routing and capability discovery. It provides tools for artifact search and graph neighbor traversal while using feedback to refine local routing hints.

yonro / hermes-xmemo-plugin

XMemo provides durable cross-session memory for Hermes Agent through pre-turn context injection and session-end snapshots. It ensures reliability using a local SQLite layer and a write outbox for searching and updating agent state.

futurebrowser / hermes-exabase-plugin

This plugin integrates Exabase M-1 to provide self-organizing long-term memory for agents. It supports configurable query expansion and result reranking to optimize the retrieval of manually stored or searched memories.

visorcraft / MongrelDB-Hermes

An AI-native memory provider that offers AES-256-GCM encryption at rest and multiple retrieval methods including HNSW ANN, sparse, and FM-index search. It supports metadata filtering and MinHash deduplication, operating via native Rust FFI or an HTTP daemon.

sourcevault-ai / sourcevault-code-tools

This plugin provides private local code memory for repositories, enabling semantic search and grounded Q&A through a local SourceVault server. It adds deterministic slash commands and LLM-callable tools for file reads and indexing synchronization.

penfieldlabs / hermes-penfield

This provider features 17 tools for memory management and knowledge graph traversal using a hybrid search of BM25, vector, and graph methods. It also performs automatic context checkpointing during message compression to maintain agent state.

conorbronsdon / agent-memory-kit

This toolkit provides a file-based curation loop that identifies data rot and contradictions within agent memory using specialized 'rot' and 'lint' curators. It utilizes a git-backed directory for versioned markdown storage and offers five slash commands to manage the capture, recall, and review of evidence-cited diffs.
