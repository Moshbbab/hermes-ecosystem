For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

This universal memory layer provides multi-level storage for user, session, and agent states using temporal reasoning and multi-signal retrieval. It is available as a managed cloud service, a self-hosted server, or an Apache-2.0 open-source SDK.

supermemoryai / supermemory

This memory engine utilizes a custom vector graph engine to deliver sub-300ms recall and byte-level deduplication for high-volume token processing. It features multi-modal extraction for diverse file types and integrates with major productivity platforms like Google Drive and GitHub via a single API.

volcengine / OpenViking

This context database uses viking:// URIs and tiered L0/L1/L2 loading to achieve significant token reduction and task-completion gains. It is an AGPL-3.0 licensed provider that supports a wide range of models including OpenAI, Ollama, and Kimi.

garrytan / gbrain

This opinionated agent brain synthesizes answers with citations and gap analysis while building a self-wiring knowledge graph with typed edges. It is designed for local deployment using PGLite to manage agent intelligence.

vectorize-io / hindsight

Hindsight implements long-term memory through specialized retain, recall, and reflect workflows that allow agents to learn over time. It offers Python and Node.js SDKs alongside Docker-based deployment options for flexible integration.

plastic-labs / honcho

This library enables stateful agents through peer-centric modeling and background reasoning, serving as the upstream foundation for self-hosted Hermes wrappers. It provides both managed and self-hosted FastAPI server options with SDKs for Python and TypeScript.

campfirein / byterover-cli

This provider treats memory as a git repository, offering version control features like branching and merging for context tree management. It utilizes a 5-tier retrieval system for sub-100ms performance and includes a React-powered TUI and REPL interface.

AxDSan / mnemosyne

Mnemosyne is a zero-dependency memory system that uses a single SQLite database to achieve sub-millisecond performance. It supports the Model Context Protocol (MCP) for integration with tools like Cursor and Claude Code.

greyhaven-ai / autocontext

This recursive self-improving context harness uses filesystem-first traces and datasets to help agents solve complex tasks. It includes CLI tools for task investigation and supports multiple providers including Pi and MCP clients.

stephenschoettler / hermes-lcm

This plugin uses a DAG-based context engine and a SQLite-backed message store to ensure no messages are lost during agent interactions. It builds depth-aware summary DAGs for history compaction and provides dedicated tools for searching and expanding context.

elkimek / honcho-self-hosted

This backend enables private, cross-session memory for Hermes Agent by self-hosting the Honcho library via Docker, PostgreSQL, and Redis. It is compatible with any OpenAI-compatible LLM provider or local inference servers.

plur-ai / plur

Plur provides a shared memory layer that stores knowledge as plain-text YAML engrams on local disk for multi-agent systems. It supports hierarchical scoping for both global and project-specific knowledge across various coding agent clients.

Signet-AI / signetai

This local-first layer manages identity, memory, and secrets across multiple agent platforms including Hermes and Claude Code. It includes a dedicated dashboard and tools for inspecting, editing, and repairing stored memory.

yoloshii / ClawMem

ClawMem is an on-device context engine that uses hybrid retrieval combining BM25 and vector search without cloud dependencies. It captures agent decisions using a local GGUF observer model and integrates via MCP or plugins.

EfficientContext / ContextPilot

This optimization tool reduces prefill latency and saves tokens by reordering blocks and deduplicating context for prefix reuse. It provides native plugin support for the Hermes Agent and OpenClaw ecosystems to accelerate long-context inference.

Sibyl-Labs / Sibyl-Memory

This file-based system provides durable long-term memory using SQLite with FTS5 search instead of vector databases or embeddings. It is delivered as a five-package plugin family that includes an SDK, CLI, and Hermes adapter.

yantrikos / yantrikdb-hermes-plugin

This self-maintaining plugin features explainable retrieval by tagging every recall with a reason and tracking contradictions in information. It includes a self-directing loop to identify knowledge gaps and uses recency ranking for memory management.

amanning3390 / flowstate-qmd

This anticipatory memory system prefetches context by monitoring agent session logs and storing data locally using SQLite-vec. It is an MCP-native server designed for major coding agents, originally created as a Hermes 2026 Hackathon entry.

yepyhun / Brainstack

Brainstack integrates Hindsight, Graphiti, and MemPalace into a single kernel stack for state and retrieval management. It utilizes SQLite, Kuzu, and Chroma to provide agents with purpose-built evidence packets for every query.

keepnotes-ai / keep

This reflective memory system uses semantic search and ranked graph traversal to create bidirectional relationships between stored notes. It features automated indexing for codebases and multimedia, including OCR support for image-based data.

alias8818 / hermes-tool-slimmer

This tool reduces prompt token overhead by using local BM25 ranking to select only the most relevant tool schemas. It includes a dashboard for tracking estimated savings and is compatible with native Hermes Agent tool search.

Perseus-Computing-LLC / perseus

Perseus resolves live workspace state into verified facts before the context window opens to reduce prompt tokens by up to 94%. It implements the Model Context Protocol and supports shell-executing directives with explicit authorization.

ccf / agentcairn

This daemonless provider uses an Obsidian vault as the source of truth, storing cross-project memory as inspectable Markdown files. It employs DuckDB as a replaceable retrieval cache and supports coding agents like Claude Code and Codex.

Ladybug-Memory / hermes-memory-plugin

This local-only plugin uses an embedded .lbdb graph database and importance-weighted ranking to surface high-priority memories. It supports BM25 keyword search and optional GLiNER2 entity extraction for structured retrieval.

MukundaKatta / hermes-agentmemory

This pull-model episodic memory plugin features real deletion of events to prevent persistent summaries from affecting future recall. It provides a trace.jsonl audit log for all memory operations and uses an on-demand summarizer.

yonro / hermes-xmemo-plugin

XMemo provides durable cross-session memory with semantic search and automatic mirroring from native Hermes memory tools. It supports session snapshots, TTL-based storage, and provenance tracking for cross-agent recall.

piprail / piprail

This SDK and MCP server allows AI agents to handle payments and charge for API usage using stablecoins across multiple chain families like EVM and Solana. It integrates directly with Hermes and other agent frameworks to enable financial autonomy.

futurebrowser / hermes-exabase-plugin

This plugin integrates Exabase M-1 for self-organizing long-term memory within the Hermes Agent. It provides tools for manual memory storage and utilizes query expansion and result reranking to optimize retrieval.

sourcevault-ai / sourcevault-code-tools

This plugin provides private local code memory for repositories, enabling semantic search and grounded Q&A across CLI and desktop interfaces. It requires a local SourceVault server to manage repo indexing and slash command functionality.

penfieldlabs / hermes-penfield

Penfield offers 17 tools for memory management and knowledge graph traversal using a hybrid search of BM25, vector, and graph methods. It also features automatic context checkpointing during message compression to preserve state.

visorcraft / MongrelDB-Hermes

This AI-native memory system features AES-256-GCM encryption at rest and supports both dense HNSW ANN and exact-text recall. It can be executed via native Rust FFI or as an HTTP daemon, providing metadata filtering and MinHash deduplication.
