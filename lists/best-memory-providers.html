For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

This universal memory layer provides multi-level state management for users, sessions, and agents through temporal reasoning and multi-signal retrieval. It is available as an Apache-2.0 self-hosted OSS SDK, a standalone server, or a managed cloud service.

volcengine / OpenViking

This AGPL-3.0 context database organizes agent memory as a virtual filesystem using viking:// URIs and a three-tier loading system. It achieves significant token reduction and task-completion gains while providing observable retrieval trajectories for debugging.

supermemoryai / supermemory

This engine utilizes a custom vector graph and byte-level deduplication to sustain sub-300ms recall at scales exceeding 100B tokens per month. It features automated fact extraction and connects to external platforms like Google Drive, Notion, and GitHub for hybrid RAG search.

garrytan / gbrain

This agent brain utilizes a self-wiring knowledge graph with typed edges to provide synthesized answers complete with citations and gap analysis. It is designed for multi-user team environments through the use of scoped access controls.

vectorize-io / hindsight

This memory system implements long-term retain, recall, and reflect workflows across more than 25 LLM providers. It supports Python, Node.js, Go, and CLI clients for both hosted and self-hosted deployment configurations.

plastic-labs / honcho

This library provides a FastAPI server and client SDKs to build stateful agents with hybrid search and prompt-ready context injection. It serves as the upstream foundation for specialized self-hosted Hermes memory wrappers.

campfirein / byterover-cli

Operating under the Elastic License 2.0, this provider manages context trees using git-like version control features such as commits, branches, and merges. It utilizes a five-tier retrieval system to achieve sub-100ms performance across 20 LLM providers.

mnemosyne-oss / mnemosyne

This zero-dependency system operates locally using a single SQLite database to provide sub-millisecond memory retrieval for Hermes Agents. It features episodic compression to ensure sub-linear storage growth and supports MCP for integration with tools like Cursor and Claude Code.

ClaudioDrews / memory-os

This seven-layer system utilizes local infrastructure including Qdrant and Redis to manage persistent memory, structured facts, and an auto-curated wiki. It employs a Ground Truth hierarchy to ensure agents prioritize specifically injected context during execution.

greyhaven-ai / autocontext

This recursive harness uses outcome-gated promotion to manage context bundles and playbooks for complex agent tasks. It is available as a Python or TypeScript library and integrates with MCP clients and OpenAI-compatible endpoints.

stephenschoettler / hermes-lcm

This plugin implements a DAG-based context engine that uses a SQLite-backed store with FTS metadata to ensure no messages are lost. It builds depth-aware summary nodes in a hierarchical structure, allowing agents to search and expand compacted material.

elkimek / honcho-self-hosted

This wrapper enables private cross-session persistence for Hermes Agent by providing a self-hosted backend for the Honcho library. It includes automated setup scripts for Docker, PostgreSQL, and Redis, supporting any OpenAI-compatible or local inference server.

Signet-AI / signetai

This local-first identity and memory layer provides portable state across Hermes Agent and other MCP clients. It achieves a 97.6% LongMemEval answer accuracy and supports data imports from Obsidian, Discord, and GitHub.

plur-ai / plur

Plur offers a shared memory layer for multi-agent systems that stores data locally as human-readable YAML engrams. It utilizes hybrid retrieval via BM25 and local embedders to integrate with tools like Claude Code and OpenClaw.

yoloshii / ClawMem

ClawMem is an on-device context engine that operates entirely locally without cloud dependencies or API keys. It employs hybrid retrieval, combining BM25 and vector search, to serve agents through MCP and dedicated plugins.

EfficientContext / ContextPilot

This optimization tool accelerates inference by reordering and deduplicating blocks to maximize prefix reuse. It offers native plugin support for Hermes Agent, reducing prefill latency by 1.5–3× and saving up to 36% in token usage.

Sibyl-Labs / Sibyl-Memory

Sibyl-Memory provides durable, file-based long-term memory using a five-package plugin family that includes a dedicated Hermes adapter. The architecture relies on SQLite with FTS5 search rather than vector databases or embeddings.

yantrikos / yantrikdb-hermes-plugin

This self-maintaining plugin features explainable retrieval by tagging every recall with a 'why_retrieved' explanation. It supports an in-process embedded mode by default and includes recency ranking and contradiction tracking for multi-user environments.

yepyhun / Brainstack

Brainstack serves as a memory kernel stack that integrates Hindsight, Graphiti, and MemPalace into a single memory owner. It manages state using SQLite, Kuzu, and Chroma to deliver purpose-built evidence packets to the agent for every query.

amanning3390 / flowstate-qmd

This anticipatory memory system prefetches context by monitoring agent session logs to populate a local cache. Built for the Hermes 2026 Hackathon, it uses SQLite-vec and GGUF models to provide an MCP-native server for coding agents.

ccf / agentcairn

AgentCairn establishes cross-project memory for coding agents by using a user's Obsidian vault as the primary source of truth. It stores memory as inspectable Markdown files and utilizes DuckDB as a replaceable retrieval cache.

generalbusiness-ai / keep

Keep provides reflective memory through semantic search, BM25 full-text indexing, and ranked graph traversal. It features automated indexing for multimedia and codebases, using edge tags to create bidirectional relationships between notes.

Perseus-Computing-LLC / perseus

Perseus resolves live workspace state into verified facts to ensure agents load only necessary context. It uses local SQLite storage and offline embeddings to reduce prompt tokens by 94% while supporting profiles for Hermes and Cursor.

alias8818 / hermes-tool-slimmer

This utility reduces Hermes Agent prompt overhead by using local BM25 ranking to select relevant tool schemas. It is compatible with Hermes Agent v0.14.0 and includes a dashboard to track estimated token savings.

Ladybug-Memory / hermes-memory-plugin

This local-only plugin utilizes an embedded .lbdb graph database to manage agent memory with a built-in 1-10 importance ranking system. It prioritizes high-value information during context prefetch using BM25 keyword search and optional GLiNER2 entity extraction.

conorbronsdon / claude-context-os

This Git-backed layer provides a shared lifecycle kernel for Hermes and other agents to store durable context and decision logs in plain Markdown. It includes a migration workflow designed to convert chat archives into reviewable, version-controlled files.

MukundaKatta / hermes-agentmemory

Focusing on episodic memory, this plugin features an on-demand summarizer and a trace.jsonl audit log for tracking all prefetch operations. It distinguishes itself by supporting immediate event deletion to ensure removed data does not persist in future recall.

yonro / hermes-xmemo-plugin

This provider enables cross-session AI memory through pre-turn context injection and session-end snapshots. It relies on a local SQLite reliability layer and a write outbox to manage tools for searching and updating agent state.

piprail / piprail

This SDK and MCP server enables Hermes agents to handle payments using USDC and stablecoins across EVM, Solana, and eight other chain families. It allows APIs to charge for access and agents to pay for services autonomously with a few lines of code.

stepanov1975 / hermes-local-knowledge

This plugin indexes local Markdown files, cron jobs, and MCP configurations to provide artifact search and retrieval capabilities. It offers five specialized tools and supports opt-in automatic tool-routing note generation via model calls.

futurebrowser / hermes-exabase-plugin

Integrating Exabase M-1, this plugin facilitates self-organizing long-term memory for Hermes agents. It includes configurable query expansion and result reranking to optimize the retrieval of manually stored or searched memories.

visorcraft / MongrelDB-Hermes

This AI-native memory solution provides AES-256-GCM encryption at rest and supports HNSW ANN, sparse, and FM-index retrieval. It can be executed via native Rust FFI or as an HTTP daemon, featuring MinHash deduplication and metadata filters.

sourcevault-ai / sourcevault-code-tools

This plugin provides private local code memory by adding deterministic slash commands for searching and syncing repositories. It requires a local SourceVault server for indexing and provides LLM-callable tools for grounded Q&A.

penfieldlabs / hermes-penfield

This provider offers 17 tools for memory management and knowledge graph traversal using a hybrid search method that combines BM25, vector, and graph techniques. It also features automatic context checkpointing during message compression.

conorbronsdon / agent-memory-kit

This file-based curation tool uses a git-backed directory to manage versioned Markdown memory without a database. It includes 'rot' and 'lint' curators to identify stale or conflicting data and proposes evidence-cited diffs for review.
