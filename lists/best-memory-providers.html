For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

This official Hermes Agent memory provider offers a universal layer for multi-level memory across user, session, and agent states. It supports temporal reasoning and multi-signal retrieval, available as an Apache-2.0 self-hosted server or a managed cloud service.

supermemoryai / supermemory

An official memory engine for Hermes that achieves sub-300ms recall and features a custom vector graph engine with byte-level deduplication. It automates fact extraction and user profile maintenance across multi-modal sources including Google Drive, Notion, and GitHub.

volcengine / OpenViking

This AGPL-3.0 context database uses a filesystem management paradigm to unify agent memories and skills via viking:// URIs. It employs tiered L0/L1/L2 loading to reduce token consumption by 91% while providing visualized retrieval trajectories.

garrytan / gbrain

An opinionated agent brain that utilizes a self-wiring knowledge graph with typed edges to provide synthesis and gap analysis for queried data. It is designed for flexible deployment, supporting both local PGLite and remote server environments.

vectorize-io / hindsight

A learning-focused memory system that implements specific retain, recall, and reflect workflows for long-term agent persistence. It offers Docker-based deployment alongside dedicated Python and Node.js client SDKs.

plastic-labs / honcho

The upstream library for stateful agents that enables peer-centric modeling and background reasoning via FastAPI. It provides both managed and self-hosted options with SDKs for Python and TypeScript.

campfirein / byterover-cli

This official provider manages memory as a git-like repository, offering version control features like branching and merging over a markdown context tree. It utilizes a 5-tier retrieval system for sub-100ms performance and includes a React-powered TUI.

AxDSan / mnemosyne

A zero-dependency, SQLite-backed memory system that provides sub-millisecond performance without requiring external services. It includes a TripleStore for temporal knowledge graph management and is compatible with MCP clients and OpenWebUI.

greyhaven-ai / autocontext

A recursive self-improving harness that distills successful agent behaviors into persistent playbooks and local-model training artifacts. It specifically exports CLI-first skills formatted for seamless Hermes agent integration.

stephenschoettler / hermes-lcm

A lossless context management plugin that uses a DAG-based engine and SQLite message store to ensure no messages are lost. It builds depth-aware summary nodes and provides specialized tools for session recall and expansion.

elkimek / honcho-self-hosted

A self-hosted backend wrapper for Honcho that enables private cross-session memory for Hermes using any OpenAI-compatible or local LLM. It includes automated setup scripts for Docker, PostgreSQL, and Redis environments.

plur-ai / plur

A shared memory layer that utilizes an open engram YAML format for plain-text storage on local disks. It supports hierarchical scoping for global and project-specific knowledge across multiple agent platforms like Claude Code and Cursor.

Signet-AI / signetai

A local-first identity and memory layer that ensures portable state and secret custody across Hermes, Claude Code, and MCP clients. It features a dedicated dashboard for inspecting and repairing stored memory files.

yoloshii / ClawMem

An on-device context engine that operates entirely locally without cloud dependencies or API keys. It uses hybrid retrieval, combining BM25 and vector search, to support Hermes and Claude Code agents.

EfficientContext / ContextPilot

A context optimization plugin that reduces prefill latency by 1.5–3× through block reordering and deduplication. It is designed to preserve accuracy while saving up to 36% in token costs for the Hermes ecosystem.

Sibyl-Labs / Sibyl-Memory

A durable, file-based memory system that avoids vector databases and embeddings in favor of SQLite with FTS5 search. This five-package plugin family includes a dedicated Hermes adapter and an MCP server.

yantrikos / yantrikdb-hermes-plugin

A self-maintaining plugin that provides explainable retrieval by tagging every recall with a 'why_retrieved' explanation. It features a self-directing loop to identify knowledge gaps and tracks contradictions for data resolution.

yepyhun / Brainstack

A memory kernel stack that integrates Hindsight, Graphiti, and MemPalace to provide purpose-built evidence packets for agent queries. It manages state and retrieval using a combination of SQLite, Kuzu, and Chroma.

amanning3390 / flowstate-qmd

An anticipatory memory system that prefetches context by monitoring agent session logs for RAG and vector search. It is an MCP-native server using SQLite-vec and local GGUF models for storage and inference.

keepnotes-ai / keep

A reflective memory tool that uses semantic search and ranked graph traversal to create bidirectional relationships between notes. It features automated indexing for codebases and multimedia, including OCR support.

alias8818 / hermes-tool-slimmer

This plugin reduces prompt token overhead by using local BM25 ranking to select only relevant tool schemas. It includes a dashboard to track estimated savings and is compatible with Hermes Agent v0.14.0.

Perseus-Computing-LLC / perseus

A context layer that resolves live workspace state into verified facts before the context window opens, resulting in 94% fewer prompt tokens. It implements the Model Context Protocol (MCP) via stdio or SSE for efficient state resolution.

ccf / agentcairn

A daemonless, cross-project memory system that uses a user's Obsidian vault as the primary source of truth. It stores memory as Markdown files and utilizes DuckDB for BM25 and semantic retrieval caches.

Ladybug-Memory / hermes-memory-plugin

A local-only plugin using an embedded .lbdb graph database that ranks memories by importance (1-10) to surface high-priority data. It supports BM25 keyword search and optional GLiNER2 entity extraction.

MukundaKatta / hermes-agentmemory

A pull-model episodic memory plugin that supports immediate event deletion and provides a trace.jsonl audit log of all operations. It uses an on-demand summarizer to prevent persistent summaries from affecting future recall.

yonro / hermes-xmemo-plugin

A durable cross-session memory provider that features semantic search, provenance tracking, and session snapshots. it automatically mirrors memory from native Hermes tools and supports TTL for stored states.

piprail / piprail

An SDK and MCP server that enables Hermes agents to handle payments and charge for API usage across multiple blockchain families like EVM and Solana. It integrates financial transactions directly into the agent's operational flow.

futurebrowser / hermes-exabase-plugin

This plugin integrates Exabase M-1 for self-organizing long-term memory with tools for manual storage and searching. It supports configurable query expansion and result reranking to improve retrieval quality.

sourcevault-ai / sourcevault-code-tools

A private local code memory plugin that provides semantic search and grounded Q&A for repositories. It requires a local SourceVault server and supports Hermes via CLI, Telegram, and Desktop interfaces.

penfieldlabs / hermes-penfield

A memory provider offering 17 tools for knowledge graph traversal and hybrid search combining BM25, vector, and graph methods. It features automatic context checkpointing during message compression to preserve state.
