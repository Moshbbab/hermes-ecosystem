For the architecture behind these tools, read The Hermes Agent Memory Guidebook.

breakdown

mem0ai / mem0

This official Hermes Agent memory provider offers a universal memory layer available as a managed cloud or Apache-2.0 self-hosted OSS. It supports multi-level memory for User, Session, and Agent states through temporal reasoning and multi-signal retrieval.

supermemoryai / supermemory

An official Hermes Agent memory provider featuring a custom vector graph engine and sub-300ms recall at 100B+ tokens/month. It provides automated fact extraction, hybrid RAG and memory search, and connectors for services like Google Drive, Gmail, and GitHub.

volcengine / OpenViking

This official Hermes Agent memory provider uses the viking:// protocol for deterministic context browsing and tiered L0/L1/L2 loading. It is an AGPL-3.0 open-source context database that has demonstrated a 91% token reduction over baselines on LoCoMo10.

garrytan / gbrain

This opinionated brain for Hermes Agents provides synthesis and gap analysis for queries. It supports multi-user scoping via login and creates typed edges without requiring LLM calls.

vectorize-io / hindsight

This memory system enables long-term retain, recall, and reflect workflows for agents. It provides Python and Node.js client SDKs and acts as an LLM wrapper for existing agents.

plastic-labs / honcho

This memory library for building stateful agents supports peer-centric modeling and background reasoning. It is available as a managed service or a self-hosted FastAPI server with Python and TypeScript SDKs.

campfirein / byterover-cli

An official Hermes Agent memory provider that manages context trees using brv vc commit, branch, and merge versioning. It features a 5-tier retrieval system with sub-100ms latency and an interactive TUI/REPL interface.

mnemosyne-oss / mnemosyne

This zero-dependency memory system uses a single SQLite database to achieve sub-millisecond performance. It supports MCP via stdio or SSE and includes a Python SDK for direct memory operations.

ClaudioDrews / memory-os

This seven-layer memory system utilizes a Ground Truth hierarchy to ensure agents prioritize injected context. It employs local infrastructure including Docker, Qdrant, Redis, and SQLite to manage vector search and structured facts.

greyhaven-ai / autocontext

This recursive self-improving context harness provides filesystem-first traces, reports, and datasets. It supports multiple agent providers, including Pi and MCP clients, and includes CLI tools for task investigation.

stephenschoettler / hermes-lcm

This lossless context management plugin uses a SQLite-backed message store and a hierarchical DAG to build depth-aware summary nodes. It provides agent tools for searching and expanding compacted material.

elkimek / honcho-self-hosted

This self-hosted backend enables private cross-session memory for the Hermes Agent. It supports local inference servers or any OpenAI-compatible LLM provider and includes an automated setup script for Docker, PostgreSQL, and Redis.

Signet-AI / signetai

This local-first layer provides portable identity, memory, and secrets for agents including Hermes Agent and Claude Code. It features source-backed recall and repairable memory with a 97.6% LongMemEval answer accuracy.

plur-ai / plur

This shared memory layer uses an open engram YAML format to store memory as plain-text. It offers local-first, zero-cost search for multi-agent systems including Hermes and Cursor.

yoloshii / ClawMem

This on-device context engine operates locally without API keys or cloud dependencies. It utilizes hybrid retrieval through BM25 and vector search and integrates via MCP and Claude Code hooks.

EfficientContext / ContextPilot

This tool optimizes context through block reordering and deduplication to enable prefix reuse. It reduces prefill latency by 1.5–3× and includes native plugin support for the Hermes Agent ecosystem.

Sibyl-Labs / Sibyl-Memory

This file-based, long-term memory architecture uses SQLite with FTS5 search instead of vector databases or embeddings. It is delivered via a five-package plugin family including a Hermes adapter and an MCP server.

yantrikos / yantrikdb-hermes-plugin

This self-maintaining plugin provides explainable recall via why_retrieved tags. It includes built-in contradiction tracking, recency ranking, and owner-scoping for multi-user environments.

amanning3390 / flowstate-qmd

This anticipatory memory system uses RAG and vector search to prefetch context by watching agent session logs. It features an MCP-native server and local-first storage using SQLite-vec.

yepyhun / Brainstack

This memory kernel stack integrates Hindsight, Graphiti, and MemPalace into a single memory owner. It manages state and retrieval using SQLite, Kuzu, and Chroma to provide evidence packets per query.

generalbusiness-ai / keep

This reflective memory system uses semantic search with BM25 and ranked graph traversal. It features automated indexing for codebases, URLs, and multimedia with OCR support.

ccf / agentcairn

This daemonless memory solution stores information as inspectable Markdown files to ensure user ownership. It uses DuckDB as a replaceable retrieval cache and supports Claude Code and Codex.

Perseus-Computing-LLC / perseus

This context layer resolves live workspace state into verified facts to reduce prompt tokens by 94%. It operates locally without hosted services and exposes context as an MCP server.

alias8818 / hermes-tool-slimmer

This utility reduces prompt token overhead through local BM25 tool ranking and keyword selection. It is compatible with Hermes Agent v0.14.0 and includes a dashboard for tracking token savings.

Ladybug-Memory / hermes-memory-plugin

This local-only plugin utilizes a single.lbdb embedded graph database to store memories. It features an importance ranking from 1-10 to prioritize high-priority recall and supports BM25 keyword search alongside optional GLiNER2 entity extraction.

MukundaKatta / hermes-agentmemory

This plugin implements a pull-model episodic memory system that supports real, immediate event deletion. It includes an on-demand summarizer and maintains a trace.jsonl audit log for every memory operation.

yonro / hermes-xmemo-plugin

This provider offers durable cross-session memory through session-end snapshots and pre-turn context injection. It utilizes a local SQLite reliability layer and a write outbox to manage state updates and searches.

piprail / piprail

This SDK and MCP server enables API charging for AI agents using USDC and stablecoins across multiple chain families, including EVM and Solana. It integrates directly with Hermes to facilitate payments.

futurebrowser / hermes-exabase-plugin

This plugin integrates Exabase M-1 to provide self-organizing long-term memory for agents. It includes tools for manual memory storage and searching, with support for configurable query expansion and result reranking.

visorcraft / MongrelDB-Hermes

This AI-native memory solution provides AES-256-GCM encryption at rest and supports both embedded and multi-mode execution via Rust FFI or HTTP daemon. It offers hybrid recall through HNSW, sparse, FM-index, and bitmap indexing.

stepanov1975 / hermes-local-knowledge

This reusable plugin provides five native tools for managing and searching local artifacts. It includes a proactive router skill and supports automatic tool-OKF generation through an opt-in process.

penfieldlabs / hermes-penfield

This provider features 17 tools for knowledge graph traversal and memory management. It employs a hybrid search method combining vector, BM25, and graph techniques, and includes automatic context checkpointing during message compression.

sourcevault-ai / sourcevault-code-tools

This plugin provides private, local code memory for repositories via semantic and literal code search. It supports grounded Q&A that includes file-and-line citations and runs locally over localhost.
